Can a sensor-based estimate skip most of the diffusion steps?

Yes, and it is well founded. Estimate the cube from the 30 sensor values, add exactly the noise that step t₀ calls for, and run only the last t₀ reverse steps. On the fully trained per-pixel model, a start of about the model's own quality plus 10 DDIM steps from t₀ = 200 reached the same mean error as full 1 000-step sampling. On that checkpoint plain 5-step DDIM from noise does too, so a speed gain over few-step DDIM is not shown here; the warm start pays off when the estimate is better than the model. The experiments also exposed two problems that matter more than speed: with the repo's noise-free simulated sensor values a closed-form linear inverse already beats every diffusion output, and the 2-D checkpoint tested here ignores which sensor values it is given.

01The idea: you only need an estimate of x₀

During training the network only ever sees $x_t=\sqrt{\bar\alpha_t}\,x_0+\sqrt{1-\bar\alpha_t}\,\varepsilon$. To start at an intermediate step you need an $x_{t_0}$ that looks like that. The noise part is known; only x₀ is missing, and a rough estimate from the sensor is enough because at t₀ it is mixed with a lot of noise.

$$x_{t_0}=\sqrt{\bar\alpha_{t_0}}\;\hat x_0(y)+\sqrt{1-\bar\alpha_{t_0}}\;\varepsilon,\qquad \varepsilon\sim\mathcal N(0,I).$$

The difference from a "true" $x_{t_0}$ is $\sqrt{\bar\alpha_{t_0}}\,(\hat x_0-x_0)$, sitting under noise of size $\sqrt{1-\bar\alpha_{t_0}}$. Their ratio, $e/\sigma(t_0)$ with $e$ the estimate's per-element RMS error, tells you how visible the shortcut is:

Why not train a model that outputs x at step t₀ directly? A network trained with MSE to output $x_{t_0}$ from $y$ learns $\mathbb E[x_{t_0}\mid y]=\sqrt{\bar\alpha_{t_0}}\,\mathbb E[x_0\mid y]$: the noise averages out, so its output has zero spread and is not a valid starting point (its covariance falls short by $\bar\alpha\,\mathrm{Cov}(x_0\mid y)+(1-\bar\alpha)I$). Adding the known noise to that output turns it back into exactly the warm start above. So the "other model" should predict x₀, and the noise is never learned. Truncated diffusion models that do learn a generator for $x_{t_0}$ (TDPM, Zheng et al., ICLR 2023) need an adversarially trained prior because they have no informative estimate of x₀ to start from: unconditional generation, or a weak condition such as a text prompt in their text-to-image variant.

02Why it is sound, and what the theory does not promise

Proposition · the start error can only shrink Let $\nu$ be the law of the warm start for a given $y$ and $q_{t_0}(\cdot\mid y)$ the true noised posterior. Applying the same Markov kernel to both can increase neither their KL divergence nor their total variation (data processing). The exact reverse kernel $K$ maps $q_{t_0}(\cdot\mid y)$ to $p(x_0\mid y)$, so
$$\mathrm{KL}\big(\nu K\,\big\|\,p(x_0\mid y)\big)\le\mathrm{KL}\big(\nu\,\big\|\,q_{t_0}(\cdot\mid y)\big)\le\frac{\mathrm{SNR}(t_0)}{2}\,\mathbb E\big[\|\hat x_0(y)-x_0\|^2\mid y\big],\qquad \mathrm{SNR}=\frac{\bar\alpha}{1-\bar\alpha},$$
with $x_0\sim p(x_0\mid y)$; averaged over $y$ the right side is $\mathrm{SNR}\cdot d\,e^2/2$, and it is non-increasing in $t_0$. A learned kernel $\hat K$ still does not amplify the start error, $\mathrm{TV}(\nu\hat K,q_{t_0}\hat K)\le\mathrm{TV}(\nu,q_{t_0})$, but $q_{t_0}\hat K\neq p(x_0\mid y)$, so the network's own error adds a second term. For DDPM-type samplers Chen et al. (ICLR 2023) bound it by a term that grows with the reverse horizon, so a smaller t₀ also means less accumulated network error; their theorem does not cover DDIM, and its constants are not measured here.
  • The guarantee is weak in high dimension. The bound sums over every element. For a whole 64 × 64 × 64 cube (d = 262 144) a useful guarantee (KL ≤ 0.1 nat, so TV ≤ 0.22) needs t₀ ≳ 620 even for the 0.29 % linear estimate; for a per-pixel model of a 64-band spectrum (d = 64) it holds from t₀ ≈ 30 with the same estimate. In practice the per-element ratio of section 1 is the more useful guide, because it measures how far each input element is from what the network saw in training, but it is a heuristic, not a theorem; the 2-D network attends across the whole patch, so locality does not rescue the whole-cube bound.
  • DDIM remembers the start more than DDPM. For a Gaussian posterior with variance $v$ and an exact score, a start offset $\delta$ survives as $\tfrac{r}{1+r}\delta$ under the exact ancestral reverse kernel and as $\sqrt{\tfrac{r}{1+r}}\,\delta$ under the probability-flow ODE that DDIM discretises, with $r=\mathrm{SNR}(t_0)\,v$. The repo's stride-1 samplers follow these within about 15 %; few-step samplers do not, so for 10-step DDIM the factors are qualitative. A bad estimate therefore needs a larger t₀ with DDIM than with DDPM, as the prior-mean start in section 3 shows.
  • CCDF's contraction theorem is the closest formal result. Chung, Sim and Ye (CVPR 2022) initialise from a cheap estimate, forward-diffuse to t₀, and show that the error contracts geometrically through the reverse steps. Its proof assumes an oracle score of a point mass at the true image. It applies formally here (with the identity as data-consistency step) but gives no usable numbers, so it supports the idea qualitatively only.

03On a well-trained per-pixel model: 10 evaluations instead of 1 000

The 1-D HASCID model (U2Net1D, 132.5 M parameters, PH5 sensor, 160 bands, trained 1 000 epochs) uses its sensor input: shuffling y between pixels raises its one-step error at t = 100 from 1.2 % to 12 %. It is the right model to test the idea on. Its own error is about 3.4 % (0.07 in cube units). Four starting estimates, each re-noised to t₀ and finished with DDPM, all fed the loader's noise-free y:

  • The start's quality sets t₀. A start about as good as the model is forgotten by t₀ ≈ 200 (median 2.21 % after DDPM from t₀ = 200 vs 2.19 % for full DDPM), so the last 200 steps, or 10 DDIM steps over them, reproduce full sampling. The prior mean needs t₀ ≈ 400 and clearly fails at 200 and below.
  • For starts at least as good as the model, truncated DDIM is as good as or better than truncated DDPM at 20–40× fewer NFE (10 DDIM steps from t₀ = 200: 3.28 % vs 3.60 % for 201 DDPM steps from the 40 dB-design start). For the prior-mean start it is worse (4.52 % vs 3.68 % at t₀ = 400), as the retention formula of section 2 predicts. Plain 5-step DDIM from noise is as cheap and as good on this checkpoint, so here the speed-ups do not compound.
  • Warm starts are also more stable. Full DDPM from pure noise diverged to NaN in 6 of 64 runs, on dark pixels, around t ≈ 700; no warm-started run with t₀ ≤ 600 diverged. Clamping the x₀ prediction to [−1, 1] inside each step also fixes it; the current DiffusionTrainer.sample does this by default.
  • When the estimate beats the model, diffusion only adds error. From the noise-free linear estimate (0.40 %) the error rises steadily with t₀: 1.16 % at t₀ = 50, 1.64 % at 100, 2.71 % at 200, 3.73 % at 600. Section 5 explains why that estimate is so good.

04On the 2-D HFD checkpoint: the network ignores which sensor values it gets

The only readable 2-D HFD model on this machine is results/2d_hsi_diffusion/HFD/R_1/l2_loss/checkpoint_epoch_101.pth: 64 bands, R_Device1, base_channels 128, 194 M parameters, ε-prediction with MSE 0.036 after 100 epochs, trained before the 10 000-file cap on classes P001–P089. (The args.json beside it is stale.) Test set: 16 patches from the unseen classes P090–P100 × 2 seeds.

A warm start cannot rescue a model that ignores y: each reverse step replaces information that came from the sensor with the network's unconditional guess, so the error grows with t₀ (1.06 % at t₀ = 10, 8.80 % at 200, 39.0 % at 600). This is an early checkpoint, so the result does not say the architecture cannot work. It is, however, consistent with the flat ε-L1 plateau of 0.151 in the later single-GPU full-grid runs: for roughly Gaussian residuals an L1 of 0.151 is an MSE of about (0.151/0.798)² ≈ 0.036, the loss of this checkpoint. A loss plateau alone cannot tell a model that ignores y from one limited by capacity (the reading in the companion report); only the y-swap test can. Those checkpoints are corrupt or on the cluster, so they could not be tested here. The y-swap test (section 7) takes a minute to run on any checkpoint.

05The linear baseline: with noise-free sensor values it wins outright

The repo computes the sensor values exactly, y = x @ R, with no measurement noise. For HFD with R_Device1 (30 filters, 31 bands) only one direction of each spectrum is unmeasured in exact arithmetic, and the training prior fills it in. The closed-form estimate $\hat x_0=\mu+K(y-R^{\mathsf T}\mu)$ then reconstructs held-out cubes almost perfectly:

The ill-conditioning of the sensor matrix (§1 of the report) matters mainly once there is noise; without noise it still makes the result depend on the solver (0.29 % with a direct solve, 0.37 % with an explicit inverse at the same regulariser), so use a whitened or SVD solve. With noise the regulariser has to grow and the estimate degrades quickly. It reaches the per-pixel diffusion model's error between 60 and 40 dB, around 50 dB; the model itself was only evaluated on noise-free y, so the true crossover lies at that SNR or lower:

Two consequences. First, in the current setup both tested diffusion models lose to a 4 ms linear solve by a factor of 8 or more. A sampler can beat it only if the network extracts more than the per-pixel linear posterior, through spatial context or a non-Gaussian prior; until a model does, its training loss and metrics say little about the method. Real cameras have measurement noise, and the benchmark should too. Second, with enough noise (below about 50 dB here) the linear estimate is no better than the model, but it is still a good, free starting estimate. That is the regime the 40 dB-design start of section 3 imitates: with noise-free y it reached full-sampling mean error in 10 NFE. Whether this holds with genuinely noisy y, and for a model trained on noisy y, is untested.

06Choosing t₀

The measurements give a simple rule: a start is forgotten once the noise level $\sigma(t_0)$ is several times larger than both the start's error and the model's own error (for the per-pixel model about 0.07 in cube units, 3.4 % RMSE). Which of the two is larger decides what to do.

Sensor super-resolution stage. The same idea applies with bilinear up-sampling of the low-resolution sensor image as the start, as ResShift and I²SB do for image super-resolution. Measured start errors on that model's normalised [−1, 1] scale are 0.010, 0.020, 0.023, 0.033 and 0.041 for d = 2, 3, 4, 6 and 8 (area down-sampling), so even at d = 8 the start is buried under noise from t₀ ≈ 60 on (σ = 0.2). How small t₀ can go depends on the SR model's own error, which needs measuring on a cluster checkpoint.

Matching the posterior covariance did not help, but was not really tested. In the 2-D experiment the fitted posterior covariance was almost zero (trace 2.3 × 10⁻³ against 4.79 for the prior), so the sampled start was effectively the mean; with a larger covariance fitted by the verifier it was slightly worse (9.04 % vs 8.77 % at t₀ = 200). In the 1-D experiment the stored covariance was numerically corrupted. The covariance is fragile with this ill-conditioned sensor matrix; use the point estimate.

07What to do

  1. Run the y-swap test on every checkpoint, starting with the cluster ones. If the prediction does not change when y is swapped between cubes, the conditioning is broken and no sampler fixes it. 
    trainer = DiffusionTrainer(prediction_type=pred_type)   # 'eps' for the l2_loss checkpoint, 'v' for the cluster FSDP runs
model.eval(); dev = trainer.device
x0, y = next(iter(val_loader))                          # [B,64,H,W], [B,30,h,w]; needs B >= 2
x0, y = x0.to(dev), y.to(dev)
t = torch.full((x0.shape[0],), 100, device=dev, dtype=torch.long)
xt, _ = trainer.q_sample(x0, t)
with torch.no_grad():
    for name, yy in [('true', y), ('swapped', y.roll(1, 0)), ('zero', 0 * y)]:
        x0_hat, _ = trainer._model_to_x0_eps(model(xt, yy, t), xt, t)
        print(name, (x0_hat - x0).pow(2).mean().sqrt().item())   # 'true' must be clearly lowest
  2. Add realistic measurement noise to y in training and evaluation, at the SNR of the real camera (and keep --ds for the low-resolution case). Without it, at full sensor resolution, a linear solve wins and the diffusion results are not informative.
  3. Report the linear baseline (0 NFE) next to every diffusion metric, with its regulariser matched to the noise level and computed by a stable whitened or SVD solve.
  4. Use the warm-start sampler once the model beats or matches the linear estimate, and compare it with plain few-step DDIM from noise: 
    x0_hat = clamp(mu + (y - mu @ R) @ K.T, -1, 1)          # per pixel, 31 bands; then interpolate to 64
steps = min(steps, t0)                                   # avoid repeated timesteps when t0 < steps
ts = torch.linspace(t0, 0, steps + 1).round().long()     # t0 = 200, steps = 10: 200, 180, ..., 20, 0
x = sqrt(ab[t0]) * x0_hat + sqrt(1 - ab[t0]) * randn_like(x0_hat)
for t, t_next in zip(ts[:-1], ts[1:]):
    x0p, _ = trainer._model_to_x0_eps(model(x, y, t.repeat(x.shape[0])), x, t)
    x0p = x0p.clamp(-1, 1)                               # clamp: also stops NaN blow-ups
    if t_next == 0: break                                # output = x0 prediction at the last t
    eps = (x - sqrt(ab[t]) * x0p) / sqrt(1 - ab[t])
    x = sqrt(ab[t_next]) * x0p + sqrt(1 - ab[t_next]) * eps   # DDIM, eta = 0
return x0p
    Choose t₀ with the rule of section 6, and check it on a few held-out cubes against full sampling.
  5. Apply the same start to the sensor-SR stage with bilinear up-sampling as x̂₀, then measure the SR model's own error to set t₀.
